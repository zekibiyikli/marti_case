# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Single-module Android app (`:app`, package `com.zekibiyikli.marticase`, minSdk 29, targetSdk 37): a location tracker that shows the user on a Google Map and drops a marker every 100 m while tracking. Kotlin, Jetpack Compose (Material 3), Koin (not Hilt), Coroutines/Flow, Room, Preferences DataStore. Documentation and UI strings are mixed Turkish/English; user-facing strings live in `res/values/strings.xml` (no hardcoded UI text).

## Commands

```
./gradlew :app:assembleDebug        # build; the check to run after every change
./gradlew :app:lintDebug            # lint (report in app/build/reports/lint-results-debug.txt)
./gradlew :app:testDebugUnitTest    # unit tests (DistanceCalculatorTest, RouteTrackerTest, template ExampleUnitTest)
./gradlew :app:testDebugUnitTest --tests "com.zekibiyikli.marticase.service.RouteTrackerTest"   # single test class
./gradlew :app:connectedDebugAndroidTest   # instrumented tests (device required; only the template test exists)
```

Maps API key: put `MAPS_API_KEY=...` in the gitignored `local.properties`. The Secrets Gradle Plugin falls back to `local.defaults.properties` (`DEFAULT_API_KEY` placeholder) and injects `${MAPS_API_KEY}` into the manifest meta-data. Never print or commit the real key.

To exercise tracking on an emulator, play `docs/marti_test_rota.gpx` from Extended Controls > Location. Its comments describe which steps should or should not add a marker (note: the first point is only a reference, no marker, so 7 markers are expected).

## Build setup quirks

- AGP 9 with built-in Kotlin: `BuildConfig` is not generated by default (detect debug via `ApplicationInfo.FLAG_DEBUGGABLE`).
- Kotlin 2.4.x is required because maps-compose pulls a Kotlin 2.4 stdlib; the root `build.gradle.kts` adds `kotlin-gradle-plugin` to the buildscript classpath for that reason. The Compose compiler plugin shares the `kotlin` version in the catalog.
- JVM target is 17 (maps-compose bytecode requires it).
- Room uses KSP (not kapt) with `exportSchema = false`.
- `res/drawable` only accepts `.xml`/`.png`; SVGs must be converted to vector drawables or they break resource merging.
- Dependencies are declared only via `gradle/libs.versions.toml`. Gradle wrapper upgrades must keep `distributionSha256Sum` in sync (`./gradlew wrapper --gradle-version X --gradle-distribution-sha256-sum <sha>`).
- The manifest declares `<uses-library android:name="org.apache.http.legacy" android:required="false" />`: the Maps SDK still loads `org.apache.http` classes, and without it the map crashes with `NoClassDefFoundError` on Android 9+.

## Architecture

Clean Architecture layers under `app/src/main/java/com/zekibiyikli/marticase/`, wired by Koin modules in `di/` (`appModules` list, started in `LocationTrackerApp`):

- `domain/`: models (`LocationPoint`, `MapStyle`), repository interfaces, one-class-per-action use cases. No Android/Maps types here (hence the domain `MapStyle` enum instead of the maps-compose `MapType`).
- `data/`: Room (`AppDatabase`, `MarkerDao`), DataStore (`SettingsDataStore`: map style and the "tracking active" flag), Fused Location (`callbackFlow`) and `Geocoder` data sources, repository implementations, entity mappers.
- `presentation/map/`: `MapScreen` (composable that takes `MapViewModel` from `koinViewModel()`), `MapViewModel` + `MapUiState` (UI state models: `MapUiState.kt`, `model/MarkerDetails.kt`), `components/`, bottom-sheet `dialogs/`.
- `presentation/permission/`: composables exposing permission/location-enabled state plus a `request` action.
- `service/`: `LocationTrackingService` and `RouteTracker`.

### Tracking flow (spans several files)

`RouteTracker` (Koin singleton, constructed explicitly in `AppModule` with its own injectable `CoroutineScope`) owns tracking so it outlives the UI. It collects `ObserveLocationUpdatesUseCase`, applies the 100 m marker rule, and writes markers to Room via use cases. `LocationTrackingService` (foreground service, type `location`, `START_STICKY`) only calls `tracker.start()/stop()` and shows the notification; it stops itself when `tracker.isTracking` becomes false. `MapViewModel` never starts tracking: it observes `tracker.isTracking`, `tracker.currentLocation`, the Room marker `Flow` and the map style, merging them into one `StateFlow<MapUiState>`. The screen starts/stops tracking by calling `LocationTrackingService.start/stop(context)` (after checking location permission, location enabled, and `POST_NOTIFICATIONS` on API 33+).

Marker rule in `RouteTracker`: the first location after start is only a reference (`anchor`); a marker is added when the distance from the last marker (or anchor) is >= 100 m. `lastMarker` is kept in memory so two quick locations cannot both pass the check before Room emits. `clearRoute()` resets the anchor to the current location, so tracking does not immediately drop a new marker.

Surviving process death: `RouteTracker.start()` persists a "tracking active" flag in DataStore; `stop()` clears it (`stop(forget = false)`, used when the system destroys the service, keeps it). On a sticky restart the service tries to resume, but a background-restarted location foreground service may be refused or get no location, so `MapScreen` also checks the flag once per launch (once permission and location are available) and restarts the service if tracking was active.

Low battery: `isBatteryLow` (`util/BatteryLevel.kt`, below 10% and not charging) is used in two places. `rememberBatteryLow()` (`presentation/battery/LowBattery.kt`) follows the sticky `ACTION_BATTERY_CHANGED` broadcast live; while it is true `MapScreen` shows an info card and disables the play button (the button is enabled only with permission granted, location on and battery fine; pausing is always possible). `LocationTrackingService` listens to the same broadcast while tracking and, when the battery turns low, stops the tracker (clearing the resume flag), posts a "tracking paused" notification on a separate channel and stops itself.

Location request (`LocationDataSource`): high accuracy, 2 s interval, 10 m minimum update distance (lets the GPS rest while the user is still; markers are 100 m apart anyway).

### Compose/Maps specifics

- Camera follow in `MapScreen`: following starts when tracking starts and stops when the user moves the map (`CameraMoveStartedReason.GESTURE`, which includes pinch zoom) or taps a marker; the location button turns it back on. Follow only applies while tracking.
- Tapping a marker animates the camera to it first, and only then opens the details sheet (opening both at once made the animation stall).
- Both bottom sheets (`ModalBottomSheet`) live in their own window; call `HideNavigationBarEffect()` inside them, since `MainActivity` hides the system navigation bar and the sheet window would otherwise bring it back.
- Hiding a sheet with an animation: `sheetState.hide()` first, then call the callback (see `DeleteRouteBottomSheet`).
- Map defaults (initial position, zoom levels) are private constants at the top of `MapScreen.kt`.
- Markers use Google Maps' default red pin (no custom icon).
